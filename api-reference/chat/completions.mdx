The Chat Completions endpoint is the primary way to interact with Parallel AI's language models. It is fully compatible with the OpenAI Chat Completions API, so any existing OpenAI integration can be pointed at Parallel AI with minimal configuration changes. Supports both standard request/response and real-time streaming via Server-Sent Events (SSE).

**Base URL:** `https://api.parallellabs.app`

**Authentication:** Include your API key in the `X-API-Key` header on every request.

<Info>
  This endpoint is OpenAI-compatible. See the [OpenAI Compatibility](/integrations/openai-compatibility) guide to learn how to migrate an existing OpenAI integration in minutes.
</Info>

## Request

**`POST /api/v0/chat/completions`**

### Request Body

<ParamField body="model" type="string" required>
  The ID of the model to use for this completion. See the Models page for a full list of available model IDs.
</ParamField>

<ParamField body="messages" type="array" required>
  An ordered array of messages representing the conversation so far. Each message is an object with the following fields:

  <Expandable title="Message object">
    <ParamField body="role" type="string" required>
      The role of the message author. One of `"system"`, `"user"`, or `"assistant"`.
    </ParamField>
    <ParamField body="content" type="string" required>
      The text content of the message.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="temperature" type="number" default="1.0">
  Controls randomness in the output. Values range from `0` (deterministic) to `2` (highly random). Lower values produce more focused, consistent responses; higher values produce more varied output.
</ParamField>

<ParamField body="max_tokens" type="integer">
  The maximum number of tokens to generate in the completion. When omitted, the model uses its default context limit.
</ParamField>

<ParamField body="stream" type="boolean" default="false">
  When set to `true`, the response is streamed back incrementally as Server-Sent Events (SSE). Each event contains a partial `delta` following the OpenAI streaming format. The stream ends with a `[DONE]` message.
</ParamField>

<ParamField body="top_p" type="number" default="1.0">
  Nucleus sampling threshold. The model considers only the tokens comprising the top `top_p` probability mass. Range: `0`–`1`. It is generally recommended to adjust either `temperature` or `top_p`, but not both.
</ParamField>

<ParamField body="frequency_penalty" type="number" default="0.0">
  Penalizes tokens based on how frequently they have already appeared in the output. Range: `-2.0` to `2.0`. Positive values reduce repetition.
</ParamField>

<ParamField body="presence_penalty" type="number" default="0.0">
  Penalizes tokens that have appeared at all in the output so far, encouraging the model to discuss new topics. Range: `-2.0` to `2.0`.
</ParamField>

<ParamField body="tools" type="array">
  A list of tool definitions the model may call. Each tool must follow the OpenAI tool definition schema, including `type`, `function.name`, `function.description`, and `function.parameters`.
</ParamField>

<ParamField body="tool_choice" type="string">
  Controls how the model selects tools. Pass `"none"` to disable tool use, `"auto"` to let the model decide, or an object specifying a particular function to force.
</ParamField>

<ParamField body="response_format" type="object">
  Specifies the format of the model's output. Pass `{"type": "json_object"}` to enable JSON mode, which guarantees the response is valid JSON.
</ParamField>

<ParamField body="stop" type="string">
  A string (or array of strings) where the model will stop generating further tokens. The stop sequence itself is not included in the response.
</ParamField>

<ParamField body="seed" type="integer">
  A fixed seed for deterministic sampling. Using the same seed and request parameters should produce the same result across calls, useful for reproducibility and testing.
</ParamField>

<ParamField body="n" type="integer" default="1">
  The number of completion choices to generate. Currently only `1` is supported.
</ParamField>

<ParamField body="user" type="string">
  An optional end-user identifier. This can help with abuse monitoring and usage attribution in your dashboard.
</ParamField>

## Response

### 200 — Success

<ResponseField name="id" type="string">
  A unique identifier for this completion, prefixed with `chatcmpl-`.
</ResponseField>

<ResponseField name="object" type="string">
  The object type. Always `"chat.completion"` for non-streaming responses.
</ResponseField>

<ResponseField name="created" type="integer">
  Unix timestamp (seconds) of when the completion was created.
</ResponseField>

<ResponseField name="model" type="string">
  The model ID that was used to generate this completion.
</ResponseField>

<ResponseField name="choices" type="array">
  An array of completion choices. Contains one item when `n` is `1`.

  <Expandable title="Choice object">
    <ResponseField name="index" type="integer">
      The index of this choice in the `choices` array.
    </ResponseField>
    <ResponseField name="message" type="object">
      The generated message.
      <Expandable title="Message object">
        <ResponseField name="role" type="string">
          Always `"assistant"` for generated messages.
        </ResponseField>
        <ResponseField name="content" type="string">
          The text content of the generated message.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="finish_reason" type="string">
      The reason the model stopped generating. One of `"stop"` (natural end), `"length"` (hit `max_tokens`), `"tool_calls"` (tool invoked), or `"content_filter"`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="usage" type="object">
  Token consumption for this request.

  <Expandable title="Usage object">
    <ResponseField name="prompt_tokens" type="integer">
      Number of tokens in the input messages.
    </ResponseField>
    <ResponseField name="completion_tokens" type="integer">
      Number of tokens in the generated response.
    </ResponseField>
    <ResponseField name="total_tokens" type="integer">
      Total tokens consumed (`prompt_tokens` + `completion_tokens`).
    </ResponseField>
  </Expandable>
</ResponseField>

```json Example Response
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1705312200,
  "model": "gpt-4o-mini",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 9,
    "total_tokens": 19
  }
}
```

### Error Responses

| Status | Meaning |
|--------|---------|
| `400`  | Invalid request — check your request body for missing or malformed fields. |
| `401`  | Authentication failed — your `X-API-Key` is missing or invalid. |
| `429`  | Quota exceeded — you have reached your rate limit or token quota. |
| `500`  | Internal server error — something went wrong on our end. |

All errors return a JSON body: `{"error": "descriptive message"}`

## Examples

### Standard Request (cURL)

```bash
curl https://api.parallellabs.app/api/v0/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},
      {"role": "user", "content": "Hello! What can you do?"}
    ],
    "temperature": 0.7,
    "max_tokens": 256
  }'
```

### Using the OpenAI Python SDK

Because this endpoint is OpenAI-compatible, you can use the official `openai` Python library by overriding the `base_url`:

```python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url="https://api.parallellabs.app/api/v0",
    default_headers={"X-API-Key": "YOUR_API_KEY"},
)

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Hello! What can you do?"},
    ],
    temperature=0.7,
    max_tokens=256,
)

print(response.choices[0].message.content)
```

### Streaming Request (cURL)

Set `"stream": true` to receive incremental token deltas as Server-Sent Events. Each line is prefixed with `data: ` and the stream closes with `data: [DONE]`.

```bash
curl https://api.parallellabs.app/api/v0/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  --no-buffer \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {"role": "user", "content": "Write me a short poem about the ocean."}
    ],
    "stream": true
  }'
```

Each streamed event looks like:

```text
data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1705312200,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{"content":"The"},"finish_reason":null}]}

data: {"id":"chatcmpl-abc123","object":"chat.completion.chunk","created":1705312200,"model":"gpt-4o-mini","choices":[{"index":0,"delta":{"content":" ocean"},"finish_reason":null}]}

data: [DONE]
```
